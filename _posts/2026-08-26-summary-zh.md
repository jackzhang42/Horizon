## [Tooltip 需要延迟，然后在相关元素之间跳过延迟](https://blog.master.dev/tooltips-need-a-delay-and-then-they-need-to-skip-it/) ⭐️ 8.0/10

这篇博客文章指出，tooltip 应在短暂延迟后再出现，但当光标在相关元素之间移动时应跳过这个延迟，通过一种基于滞后（hysteresis）的方法来提高响应性。 这个细微的交互细节能显著减少工具提示意外闪烁，并提升用户感知的响应速度，带来更好的体验。它也提供了一种具体而有原则的技术，让 UI 设计师和开发人员可以在自己的应用中实现。 该技术本质上是一种滞后现象：当指针悬停在带 tooltip 的元素上时，“温度”上升，离开后降温，只有温度超过阈值时 tooltip 才显示。在相关元素之间移动时温度保持较高，因此会跳过延迟。

hackernews · ibobev · 8月25日 16:35 · [社区讨论](https://news.ycombinator.com/item?id=49436786)

**背景**: Tooltip（悬停提示）是一种常见的 UI 模式，鼠标悬停时显示一个小标签以提供额外上下文。较简单的实现会立即显示提示，这会在用户只是移动光标时导致闪烁。滞后（hysteresis）是物理学和工程学中的一个概念——一个输出既取决于当前输入也取决于过去的历史——可以用来解决这类交互问题。文章还提到，其中一些修复早在几十年前的苹果 System 6 中就已出现，但这个问题仍不断重现。

**社区讨论**: 评论者对这一细腻的分析表示赞赏。有人回忆说，苹果的 Jef Raskin 几十年前就描述过这类修复；另一些人将这一技术与一篇动画设计文章中的类似示例联系起来；还有人提到 Visual Studio 的悬停弹窗出现太快、很烦人，正好说明了文章观点的实际重要性。

## [Firefox 157 将默认启用 JPEG XL](https://groups.google.com/a/mozilla.org/g/dev-platform/c/3YMV4MS34KA?pli=1) ⭐️ 8.0/10

Mozilla 宣布 Firefox 157 将在所有平台上默认启用 JPEG XL 支持。这使 Firefox 成为首个无需用户手动开启即可使用这种新一代图像格式的主流浏览器。 此举将显著推动 JPEG XL 的普及，并可能加速该格式在网页中的集成，尤其是据报道 Chromium 也计划跟进。一旦获得近乎普遍的浏览器支持，开发者就能利用 JPEG XL 卓越的压缩率和画质，长期来看有望逐步取代传统 JPEG。 JPEG XL 是 ISO/IEC 18181 定义的自由开放标准，支持有损和无损压缩。值得注意的是，社区讨论显示 Firefox 和 Chromium 都在使用基于 Rust 语言的 jxl-rs 实现，这引发了关于其与 Apple 基于 C++ 的 libjxl 集成之间性能比较的讨论。

hackernews · yboris · 8月25日 17:55 · [社区讨论](https://news.ycombinator.com/item?id=49437946)

**背景**: JPEG XL 是由联合图像专家组（JPEG）与 Google 和 Cloudinary 合作开发的图像格式。与传统 JPEG 相比，它提供了显著更好的压缩率和图像质量，并专为无需硬件加速的高效软件编码/解码而设计。它支持高动态范围和广色域，并具有渐进式渲染功能，仅需加载 1% 的数据即可显示图像。
